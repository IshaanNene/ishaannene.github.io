# 3D asset pipeline

Every island, bridge and tree in the archipelago is real geometry generated by
Blender (via the `bpy` Python module) and exported as GLB. The `.blend` sources
are saved next to the exports so any model can be opened, sculpted and
re-exported by hand.

```
config/world.json                 ← island positions, radii, seeds, bridges (single source of truth)
scripts/blender/
  lib.py                          ← materials, mesh primitives, Builder, vertex-AO bake, GLB export
  generate_islands.py             ← heightfield terrain, layered rock foundation, ponds, waterfalls, paths, vegetation scatter
  generate_buildings.py           ← one build_<island>() per destination + content slots
  generate_environment.py         ← vegetation variants, 4 bridge types (plank / truss / arch / suspension)
  generate_textures.py            ← tiling normal + roughness maps (public/textures)
  export_assets.py                ← entry point: builds everything, writes GLBs + manifest
scripts/optimize-glb.mjs          ← meshopt compression (gltf-transform)

assets-src/blender/{islands,bridges,vegetation}/*.blend   ← editable sources
public/models/islands/<id>.glb + <id>_lod1.glb            ← LOD0 (full) / LOD1 (far)
public/models/bridges/<from>_<to>.glb
public/models/vegetation/vegetation.glb
src/generated/world-manifest.json                         ← slots, vegetation transforms, outlines, bridge ports
```

## Regenerating

One-time setup (Blender as a Python module needs Python 3.11):

```bash
uv venv .venv-blender --python 3.11 && uv pip install --python .venv-blender bpy==5.0.1
```

Rebuild every asset and compress:

```bash
npm run assets
```

Rebuild only some islands (vegetation is regenerated only when no ids are given; the manifest is merged):

```bash
.venv-blender/bin/python scripts/blender/export_assets.py blogs research && npm run assets:optimize
```

Textures: `.venv-blender/bin/python scripts/blender/generate_textures.py`.

Generation is deterministic — each island has a `seed` in `config/world.json`.

## What is in an island GLB

Nodes are grouped by name prefix. The runtime splits them by prefix, so keep
these names if you edit a model by hand:

| Node prefix | Runtime behaviour |
|---|---|
| `terrain` | grass top, paths, pads — receives shadows, raycast target for grounding content |
| `foundation` | layered rock underside (strata, overhangs, hanging rocks) |
| `buildings`, `landmarks`, `props` | static architecture, casts shadows |
| `water_*` | swapped to the animated water material |
| `waterfall_*` | swapped to the streaming waterfall shader |
| `anim_spin_*` / `anim_bob_*` / `anim_bounce_*` | animated at runtime (bounce reacts to hover/click) |

Vertex colour `COLOR_0` carries a baked, ray-traced ambient occlusion pass.
UVs are world-scale box projections so tiling textures line up across meshes.

## Material naming contract

GLB materials are named `M_<preset>` (e.g. `M_stone_light`, `M_wood_dark`,
`M_glass`, `M_emit_lime`). At load time `src/three/materials.ts` replaces each one
with a shared runtime PBR material (colour, roughness, metalness, normal map,
foliage wind). Unknown names render magenta so they are easy to spot. To add a
material: add it to `MATERIALS` in `scripts/blender/lib.py` and to
`ENV_MATERIALS` in `src/three/materials.ts` with the same key.

## Replacing a model with a hand-made one

1. Open `assets-src/blender/islands/<id>.blend` (or start fresh), keep the island
   centred at the origin at the same radius, and keep the node prefixes above.
2. Export glTF Binary (+Y up, apply modifiers, include vertex colours) to
   `public/models/islands/<id>.glb`. Export a lighter copy as `<id>_lod1.glb`
   (or copy the same file — LOD1 is only shown from far away).
3. `npm run assets:optimize`.
4. Content slots and bridge landing ports live in `src/generated/world-manifest.json`;
   if you move paths or plazas, update `slots` for that island
   (`{ "kind": "content", "pos": [x, y, z], "facing": [dx, dz] }`, three.js axes,
   island-local metres) so Markdown objects still land on open ground.

Bridges are standalone GLBs in world space; vegetation is one GLB with one node
per variant (`broad_a`, `broad_b`, `conifer`, `cypress`, `bush`, `rock`, `palm`)
instanced from manifest transforms.

## Content objects with external models

Any content entry can set `visual.modelPath: /models/content/<file>.glb`. The model
is auto-scaled to the slot footprint, placed on a plinth and the entry title is
still rendered in 3D type in front. If the file fails to load, a stone slab is
rendered instead (error boundary).

## Performance budget

- 7 islands × (LOD0 ≈ 0.4–0.8 MB, LOD1 ≈ 0.2–0.3 MB) after meshopt; 6.8 MB total models.
- LOD1 loads first for every island; LOD0 streams in when the camera comes near.
- Vegetation, rocks and trees are GPU-instanced; raycasts use `three-mesh-bvh`.
- Shadows re-render on a cadence, not every frame; post-processing is high-quality only.
- `PerformanceMonitor` drops DPR and effects on slow devices; coarse pointers start in low quality.

## Third-party assets (all free to reuse)

| Asset | Source | Licence | Used for |
|---|---|---|---|
| `public/textures/pbr/rock` | Poly Haven — rock_face_03 | CC0 | island cliffs (foundation nodes) |
| `public/textures/pbr/grass` | Poly Haven — leafy_grass | CC0 | island tops, grass content objects |
| `public/textures/pbr/planks` | Poly Haven — weathered_planks | CC0 | timber (bridges, signposts) |
| `public/textures/pbr/concrete` | Poly Haven — concrete_wall_008 | CC0 | concrete buildings and blocks |
| `public/textures/pbr/stone` | Poly Haven — sandstone_cracks (desaturated) | CC0 | carved tablets, island name stones |
| `assets-src/fonts/*.ttf` → `public/fonts/*.json` | Google Fonts — Cinzel, Bangers, Archivo Black, Fredoka | OFL | 3D lettering (`node scripts/convert-fonts.mjs`) |
| Sky, Water, MeshSurfaceSampler | three.js examples (bundled) | MIT | sunset sky, ocean, grass fur |

PBR sets are 1k WebP (colour, normal, roughness). Materials opt in with
`pbr: "<key>"` (runtime: `ENV_MATERIALS` in `src/three/materials.ts`; content:
`surface.pbr` in `src/presets/materials.ts`). Island undersides automatically use
the rock set via the `cliff_*` material variants.
